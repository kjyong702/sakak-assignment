# AI 도구 사용 기록

## 사용 도구와 범위

- 도구: Claude Code (Anthropic)
- 범위: `health-assistant/` 전체. 계획 문서 초안, 코드 작성, 테스트 작성, 문서 정리
- 방식: 문서 선행. `CLAUDE.md`(작업 규칙)와 `docs/plan.md`(구현 계획)를 먼저 만들어 상시 프롬프트로 두고
  단계마다 계획서의 해당 절을 가리키며 작업했다. 코드가 계획과 달라지면 계획서를 먼저 고쳤다
- 설계 판단: 계획서의 설계(그래프 구조, 판정을 코드가 하는 것, 호출 1회 제한, 검증 후 재생성)는 AI 도구와의
  대화로 초안을 만들고 작성자가 검토해 확정했다. 근거와 접은 대안은 계획서 3절과 9절에 있다
- 검증: 단계마다 pytest 전량 통과와 ruff 통과를 확인한 뒤 커밋했다. 테스트는 Ollama 없이 돌도록 가짜 LLM과
  `httpx` 전송 계층 교체로 만들었다. 프롬프트는 실제 모델 응답을 읽고 사람이 평가했다 (`docs/prompt-iterations.md`)
- `look-and-say/`는 풀이 접근과 설계 판단을 작성자가 직접 했고, 도구는 테스트 도구 세팅, 파이썬 문법 옮기기, 실행 진입점, 문서 정리에 썼다

## 프롬프트 기록

상시 프롬프트: `CLAUDE.md`, `docs/plan.md`. 아래는 단계별로 준 지시의 요지다.

### 0. 계획 수립

> 과제 안내서의 요구를 표로 해석하고, 구조, 그래프 설계, 참고치 파싱, 프롬프트, 테스트 전략, 실행 방식,
> 모델 비교 방법, 검토했다가 접은 대안, 단계 순으로 계획서를 써라. LLM 호출은 안내서가 지정한
> `/api/generate`만 쓴다. 로컬 7b 모델 기준으로 지연과 정확도를 고려해 판단 근거를 적어라.

### 1. Mock API

> 계획서 2절의 구조로 `GET /api/health/{patientId}`를 만들어라. 응답 키는 안내서와 1:1로 같아야 하고
> 정상(B)와 질환의심 행에 안내서에 없는 키를 만들지 마라. 없는 환자는 404. 환자 ID는 파일 경로에 들어가므로
> 허용 문자를 제한하라. 환자 2는 검진 2회분과 이상 수치를 넣어라. 테스트는 서버 없이 `ASGITransport`로.

### 2. 참고치 파싱과 판정

> 계획서 4절 표의 형태만 파싱하고 나머지는 판정 없음으로 둬라. 판정 순서는 질환의심, 정상(B), 정상(A).
> 혈압은 수축기/이완기를 따로 보고 "이며"는 둘 다, "또는"은 하나만. 성별 분기는 남녀 판정이 같을 때만
> 확정하라. 경계값(100, 125, 126, 120/79, -1, -2.5)을 테스트로 고정하라.

### 3. 그래프와 Ollama 클라이언트

> 계획서 3절 그래프를 LangGraph `StateGraph`로 만들어라. LLM 노드는 하나. 검증 노드는 답변의 수치가
> 컨텍스트에 있는지만 보고 없으면 사유를 프롬프트 앞에 붙여 한 번 재생성. Ollama는 `/api/generate`만
> 쓰고 연결 실패와 모델 없음은 사용자가 바로 조치할 수 있는 문장으로 바꿔라. 항목 키워드 중 한 글자짜리는
> "시간"의 "간"에 걸리지 않게 하라. 가짜 LLM과 `MockTransport`로 테스트.

### 4. 채팅 API와 터미널 대화

> 그래프를 감싼 서비스 계층을 두고 `POST /api/chat`과 `python -m app.chat`이 같이 쓰게 하라. 에이전트의
> Mock API 호출은 같은 프로세스에서 ASGI로. Ollama가 없으면 503과 조치 문장, 터미널은 종료 코드 2.
> 계획서 구조 절을 실제 파일 구성에 맞춰 고쳐라.

### 5. 모델 비교

> 같은 질문 세트를 후보 모델에 돌려 답변, 지연, 검증 결과를 표로 남기는 스크립트. 첫 호출의 모델 로딩
> 시간은 워밍업으로 분리하고 원본은 JSON으로 보존. 품질 판단은 사람이 적는다.

### 5-1. 실제 모델로 프롬프트 개정

> qwen2.5:7b로 안내서 예시 질문 2개와 이상 수치 환자 질문을 돌려 답변을 평가하라. 문제마다 프롬프트로 고칠 수
> 있는지 코드로 막아야 하는지 나누고, 개정마다 답변 원문과 평가를 `docs/prompt-iterations.md`에 남겨라.
> 지시로 막히지 않는 오류(보류 항목 앞세우기, 판정 오독, 무관 항목 끼워 넣기)는 컨텍스트 축소와 검증 노드
> 확장으로 막아라.

### 6. 문서

> README에 실행 방법을 명령 그대로, 동작 구조, 강조할 설계, 한계와 보완 계획을 써라. 모델 비교 결과와
> 스크린샷은 실행 후 채운다.

### 7. 제출 전 검토

> 안내서의 평가 기준 4개(Mock API 정확성, LLM 연동과 응답 품질, 코드 품질과 설계, 실행 용이성과 문서화)와
> 커밋 히스토리 점검을 렌즈로 나눠 각각 독립적으로 리포를 검토하고, 발견마다 실제로 재현해 반박 검증하라.
> 리포 파일은 수정하지 말고 문제만 보고하라.

검토 결과 55건 중 상위 10건을 검증해 9건이 확인됐고 전부 고쳤다 (경위는 `docs/prompt-iterations.md` v3.5).
확인된 것 중 큰 것은 이전 검진 포함 시 판정 검사가 정답을 오탐하던 버그와 Ollama 오류 처리 범위였다.
