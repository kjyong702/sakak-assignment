답변을 읽고 문항마다 셋 중 하나로 표시했다. O = 수치와 판정이 맞고 규칙을 따름, △ = 오류가 있었으나 검증 노드가
잡아 `verified: false`로 표시됨, X = 오류가 있는데 검증이 놓쳐 통과로 나감.

| 문항 | qwen2.5:7b | gemma3:4b | llama3.1:8b |
|---|---|---|---|
| 1. 전체 요약 (환자 1) | O 혈압 경계 먼저, 나머지 정상(A) 묶음 | △ 공복혈당 95를 정상(B)라 함 | O 정확하지만 5문단 |
| 2. 콜레스테롤 (환자 1) | O | △ HDL, LDL을 정상(B)라 함 | O 판정은 맞으나 "근소하게 정상(A)" 같은 어색한 문장 |
| 3. 혈압 (환자 2) | X 판정은 맞으나 끝에 "다른 검사 항목은 정상"이라 함. 환자 2는 아니다 | O 두 문장으로 정확 | O 참고치 표를 그대로 인용 |
| 4. 간 수치 (환자 2) | O ALT 질환의심, AST 정상(A), 감마 성별 보류 | X 질환의심 ALT를 "경계 범위"라 함 | X AST 정상이라 하고 "ALT와 AST 모두 정상이 아닌 수치" |
| 5. 작년과 비교 (환자 2) | △ 두 시점 수치는 맞으나 BMI와 공복혈당(정상(B))에 질환의심을 붙임 | O 2024년 정상(B) 목록과 2025년 질환의심 목록이 정확 | O 간결하고 정확 |
| 6. 당뇨인가요 (환자 1) | O 정상(A), 단정 없음 | △ 정상(A)라 하고 "질환의심 수치"라 함 | △ "약간 높은 편인 경우"로 흐림 |
| 합계 | O 4, △ 1, X 1 | O 2, △ 3, X 1 | O 4, △ 1, X 1 |

관찰:

- **qwen2.5:7b**는 규칙(검진일 먼저, 값과 단위, 판정 이름, 정상(B)의 표현)을 가장 잘 따르고 답이 안내서 예시와 같은
  구조다. 놓친 오류는 항목 이름 없이 "다른 항목은 정상"이라고 뭉뚱그린 문장인데, 이는 항목 검사가 이름을 기준으로
  하므로 잡지 못하는 유형이다. 이 문서를 만드는 동안 세 번 돌렸고 한 번은 답변 끝에서 중국어로 넘어갔다
  (`prompt-iterations.md` v3.7). 그 뒤 언어 검사를 붙였다
- **llama3.1:8b**는 이번 실행에서 판정 정확도가 qwen과 같았다. 그러나 "안녕하세요. 홍길동님." 인사와 문단 나누기로 답이
  두 배 길고, 4번처럼 앞 문장과 모순되는 결론을 붙이는 일이 있다. 정상(A) 항목에 "약간 높은 편"을 붙이는 습관도 있다
- **gemma3:4b**는 가장 빠르지만(평균 14초) 정상(A) 항목에 정상(B)나 질환의심을 붙이는 오류가 잦다. 검증이 세 번 잡았고
  한 번은 판정 이름 없이("경계 범위") 틀려 놓쳤다. 5번 비교 질문은 셋 중 가장 정확했다
- 요약 표의 "검증 통과"는 품질 지표가 아니라 **검증이 잡은 오류의 수를 반영**한다. 그래서 사람이 읽어 X를 따로 셌다.
  같은 모델도 실행마다 답이 갈리므로(qwen 세 번: O4/△2, O4/△1/X1, O4/△1/X1) 한 번의 표로 우열을 단정하지 않는다

선택: **qwen2.5:7b를 기본 모델로 둔다.** 정확도는 llama와 같고, 규칙 준수와 답의 구조와 한국어 자연스러움이 가장 좋다.
llama3.1:8b는 장황함과 모순 문장 때문에 2순위, gemma3:4b는 속도가 필요할 때의 대안이다.

주의: 지연 시간은 Apple M3 16GB 기준이고 재생성이 있으면 두 배가 된다. 표의 시간은 재생성을 포함한다. 5번 문항은
이전 검진까지 컨텍스트가 두 배라 어느 모델이든 60~70초 걸린다.
